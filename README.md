# 直播节目串联单

用 Python Flask + SQLite + 原生 JavaScript 实现的直播节目串联单（rundown）工具。

## 快速开始

```bash
docker compose up --build
```

启动后在浏览器打开：**http://localhost:8000**（端口 `8000`）。

- 首次启动自动创建 SQLite 数据库（容器内 `/data/rundown.db`，通过命名卷 `rundown-data` 持久化）。
- 重启容器后仍可查看实况与待播排期。
- 停止：`docker compose down`（加 `-v` 会连同数据一起删除）。

### 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
python app.py
```

同样访问 http://localhost:8000 。数据库默认写在 `./rundown.db`，可用环境变量 `DB_PATH`、`PORT` 覆盖。

## 使用流程

1. **创建节目**：设置节目起点（日期时间）与总秒数，按播出顺序录入清单：
   - 赞助段：固定时长；
   - 访谈段：最短 / 目标 / 最长秒数。
   提交时自动排程，无法恰好排满总时长会给出差额并拒绝创建。
2. **直播进行**：页面显示每段预计起止时间、当前段、已播 / 剩余时长与预计终点。
   每结束当前段，录入实际秒数并确认；系统按实际已播总时长重排余下清单。
3. **编辑待播清单**：一次编辑整份未播清单，可插入、删除、移动访谈段，
   或调整访谈段的最短 / 目标 / 最长秒数；赞助段的时长与先后顺序不可变。
4. **备播方案**：在编辑待播清单时为方案命名并点击「存为备播方案」，
   可保存多套另一种访谈编排。保存与查看备播均**不改变**正在播出的清单；
   页面按最新实播记录重算每份备播的起止时间，排不满会显示差额。
   点击「启用并替换待播」时一次性替换待播清单与排期（详见下文校验规则）。
5. **重置节目**：删除整档节目、全部记录与备播方案，重新开始。

## 排程规则

- 剩余时间 = 节目总秒数 − 实际已播总秒数。
- 先沿用各访谈段的目标时长（赞助段为固定时长）；
  差额按清单顺序在各访谈段的 [最短, 最长] 范围内分摊：
  有富余则从前到后依次拉长（至多拉到最长），超时则从前到后依次压短（至多压到最短），
  使待播清单恰好排到节目终点。
- 无法排满或仍然超时：返回具体差额（“仍差 X 秒” / “超出 X 秒”）并**拒绝**此次创建或编辑。
- 录入实际秒数导致余下清单无解时：**已播记录必须保留**，页面显示冲突横幅与差额，
  待播段暂按目标 / 固定时长展示，可再次编辑待播清单解决冲突。
- 已播记录不可改写。

## 备播方案

- 在「编辑待播清单」面板中编排好另一种访谈顺序/参数后，填写名称并点击
  **「💾 存为备播方案」**：沿用与编辑待播相同的赞助约束和排程规则，
  按保存时的最新实播校验能否排到节目终点，排程失败则该备播不保存。
- 备播是保存时的**快照**：记录当时的待播编排（赞助段与访谈段参数，访谈段通过 id
  引用当时的待播旧段）与已播段数量（保存点）。
- **保存及查看都不改变正在播出的清单**：备播列表的起止时间按每次刷新时的最新
  实播总时长重算（已播部分按实际秒数推进时间轴，其余部分按最新剩余时间尽力排程）；
  若已无法排满，显示「仍差 X 秒 / 将超时 X 秒」。
- **启用校验**（全部满足才能启用，否则弹窗说明原因，原清单、冲突、已播记录及
  备播方案均不变）：
  1. 保存备播后已播的段，必须是备播原清单中同序的开头（按段落一一对应）；
  2. 备播引用的其余旧段仍处于待播；
  3. 备播中的其余赞助段与现行待播赞助段顺序、时长一致；
  4. 按最新实播总时长，备播余下部分能恰好排到节目终点。
- 校验通过后**一次性替换**待播清单与排期并清除已解决的冲突；之后仍可照常录入
  实播和编辑。重启容器后备播仍可查看；重置节目时与节目数据一并清除。

## 接口简介

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 单页应用 |
| GET | `/api/state` | 当前实况、待播排期与备播方案（含按最新实播重算的评估） |
| POST | `/api/show` | 创建节目与初始清单 |
| POST | `/api/segments/complete` | 结束当前段，录入实际秒数 |
| POST | `/api/rundown/edit` | 整体替换待播清单（赞助段锁定） |
| POST | `/api/backups` | 把编辑区编排存为命名备播方案（不影响当前清单） |
| POST | `/api/backups/<id>/activate` | 校验后一次性启用备播替换待播清单 |
| POST | `/api/backups/<id>/delete` | 删除一份备播方案 |
| POST | `/api/show/reset` | 删除整档节目（含备播方案） |
